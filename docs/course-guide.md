# 模擬使用指引

## 建議三小時模擬

### 0:00–0:20 情境簡報
- 介紹任務、角色、成功條件及安全界線。
- 各組取得不同版本的情報。
- 使用者不得直接查看管理者真實狀態欄位。

### 0:20–0:50 任務分析
使用者回答：
1. 必須達成的核心目標是什麼？
2. 哪些是已知事實、推測及未知？
3. 對手最可能及最危險的行動是什麼？
4. 有哪些政治、民事、後勤與時間限制？

### 0:50–1:20 行動方案
- 至少提出兩個方案。
- 比較資源、風險、可逆性與後續選項。
- 決定主要方案並說明保留方案。

### 1:20–2:20 回合推演
- 每回合5–10分鐘。
- 使用者提交行動、區域、資源與理由。
- 白方發布情報及事件。
- 系統結算後，管理者可口頭修正或補充裁決。

### 2:20–3:00 事後檢討
- 查看決策時間線。
- 找出關鍵假設、情報落差與資源轉折點。
- 進行反事實討論。
- 完成個人反思。

## 建議分組
- 藍方：4–6人
- 紅方：4–6人
- 琥珀方：2–4人
- 白方與觀察評量：管理者＋2–4人

## 評量規準
| 構面 | 比例 |
|---|---:|
| 任務與成功條件 | 20% |
| 情報與證據 | 20% |
| 資源與後勤 | 20% |
| 紅隊思維與應變 | 15% |
| 民事、法律與升級風險 | 15% |
| 事後反思 | 10% |

## 管理者注意事項
- 不應將系統輸出的數字當成真實戰果預測。
- 若人工修正結果，需說明依據。
- 鼓勵使用者提出「需要哪些資料才能更有把握」，而不是追求唯一答案。
- 可將同一想定用不同種子重跑，比較決策是否具有穩健性。


## STORM 作戰研究單元（建議90至120分鐘）

### 第一段：模型結構（20分鐘）
- 點選「系統 → 能力 → 計畫 → 執行 → 影響」。
- 將既有想定資料分配到五種表徵。
- 討論缺少某一表徵會造成什麼偏差。

### 第二段：單次結果與分布（25分鐘）
- 先請使用者預測一次結果。
- 執行30次，再執行300次。
- 比較平均值、5–95百分位及90%平均值區間。
- 討論「結果變穩定」與「模型變正確」的差別。

### 第三段：COA比較（20分鐘）
- 使用相同條件與種子比較四種方案。
- 不只比較任務效果，也比較準備度、資源與民事風險。
- 要求使用者提出多準則決策理由。

### 第四段：因子實驗（25分鐘）
- 執行2³設計。
- 排序C2、ISR、後勤與交互作用。
- 討論為何單獨調整一個因素可能看不到交互作用。
- 請使用者提出下一輪應增加的因素或水準。

### STORM單元評量題
1. 為什麼不能只跑一次模擬？
2. 增加重複次數可以解決哪些問題？不能解決哪些問題？
3. 主效應與交互作用有何差別？
4. 為何平均較高的COA不一定是最佳方案？
5. 哪些參數最需要公開來源、專家判斷或校準？
