Skill 介紹

publish-to-github-catalog 是一個教學型 Codex agent skill。它不是替使用者保管帳號， 而是一步一步引導使用者完成 GitHub 帳號建立或登入、Git repository 初始化、公開 repository 建立、 程式碼上傳、README 與安裝說明整理，以及作品清單投稿。

搭配的公開網站會讀取 catalog/*.yaml，顯示作品名稱、描述、作者 GitHub、原始碼、 安裝方法、標籤、授權與 GitHub Stars。Stars 由平台建置時從 GitHub API 取得，投稿者不需要手動填寫。

什麼時候使用

  • 使用者完成了一個程式作品，想發布到自己的 GitHub 帳號。
  • 使用者沒有 GitHub 帳號，需要被引導建立帳號。
  • 使用者有 GitHub 帳號，但不熟悉 git、gh 或 Pull Request。
  • 課程或社群希望把學員作品集中成一個像軟體清單的公開網站。
  • 管理者希望以 GitHub Stars 作為公開人氣或評分指標。

使用前準備

開始前，使用者最好先確認這些項目：

  • 一個可以公開分享的程式作品資料夾。
  • GitHub 帳號；若沒有，skill 會引導前往 https://github.com/signup 建立。
  • 本機已安裝 git。
  • 建議安裝 GitHub CLI，也就是 gh，用來登入、建立 repo、開 PR。
  • 作品不應包含密碼、API key、私人資料、.env 或不該公開的檔案。

操作流程

確認作品資料夾 Codex 先確認要發布的專案位置，檢查目前是否已經是 git repository。
確認 GitHub 帳號 若使用者沒有帳號，引導到 GitHub 官方註冊頁；若已有帳號，進入 CLI 登入流程。
使用 GitHub CLI 登入 透過 gh auth status 檢查狀態，需要時執行 gh auth login。
整理公開專案內容 補 README、安裝方法、授權、.gitignore，並排除 secrets 與不該公開的檔案。
建立並推送 GitHub repository 使用 git commit 與 gh repo create 將作品發布到使用者自己的 GitHub 帳號。
建立 catalog 投稿資料 使用 npm run new-entry 產生 catalog/<slug>.yaml。
驗證並送出 Pull Request 跑 npm run validate:catalog，通過後建立分支並開 PR 到中央作品清單。

作品清單投稿

每個作品使用一個 YAML 檔案登錄，欄位如下：

name作品名稱。
description給讀者看的簡短描述。
authorName作者顯示名稱。
authorGitHubGitHub 使用者名稱。
repoowner/name 格式的 repository。
homepage作品網站，可留空。
tags1 到 8 個短標籤。
language主要語言或框架。
install安裝或執行方法，可多行。
license授權資訊。
submittedAt投稿日期，格式為 YYYY-MM-DD。
不要在 YAML 裡填 stars、forks、repoUrl 或 avatarUrl。 這些資料會由網站建置流程自動從 GitHub 取得。

常用指令

檢查工具與登入

git --version
gh --version
gh auth status
gh auth login

發布作品到 GitHub

git status
git init
git add .
git commit -m "Initial public release"
gh repo create <repo-name> --public --source . --remote origin --push

新增作品清單投稿

npm run new-entry
npm run validate:catalog

建立 Pull Request

git checkout -b add-<project-slug>
git add catalog/<project-slug>.yaml
git commit -m "Add <project-name> to catalog"
git push -u origin add-<project-slug>
gh pr create --fill

安全原則

這個 skill 永遠不應要求使用者把 GitHub 密碼、token、兩階段驗證碼、recovery code 貼到對話裡。 登入必須透過 GitHub CLI 的瀏覽器或裝置授權流程，由使用者自行完成。
  • 發布前檢查 .env、API key、資料庫密碼、私人資料是否被排除。
  • 若專案已有 git history 或 remote，先檢查再操作，不覆蓋既有設定。
  • 如果作品不適合公開，先停下來整理授權與資料，再推上 GitHub。
  • PR 投稿只登錄公開 repository，不收錄本機資料夾或私有 repo。

常見問題

使用者沒有 GitHub 帳號怎麼辦？

請使用者自行到 GitHub 官方註冊頁建立帳號。帳號完成後，再回到 Codex 繼續登入與發布流程。

沒有安裝 gh 可以用嗎？

可以，但流程會比較手動。建議安裝 GitHub CLI；若不能安裝，Codex 可以改用 GitHub 網頁介面引導建立 repo， 再用一般 git remote/push 或網頁上傳完成發布。

Stars 什麼時候會出現在網站？

投稿者不需要填 Stars。PR merge 後，GitHub Actions 在建置網站時會從 GitHub repository API 取得最新 Stars， 然後顯示在作品卡片上。

PR 驗證失敗通常是什麼原因？

常見原因包括 YAML 欄位格式錯誤、repo 不是 owner/name 格式、repository 不是公開可讀、 tags 超過 8 個，或 submittedAt 不是 YYYY-MM-DD。
