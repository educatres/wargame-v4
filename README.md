# Wargame v4｜臺海想定生成

一套可直接部署到 GitHub Pages、也可在電腦上以瀏覽器單機開啟的想定模擬與作戰研究分析系統。

**線上版本：** https://educatres.github.io/wargame-v4/

版本 4.0 新增 OpenStreetMap 真實座標配置、自適應經緯格線、區域編號、品項級武器數值裁決、公開設施中心點部署預設、經緯度回合動畫、逐回合消耗帳本，以及只使用匿名化摘要的 LLM 次回合想定生成。系統仍包含 **STORM（Synthetic Theater Operations Research Model）概念分析實驗室**；本模組是依公開文獻重新設計的模擬版，不是正式 STORM 軟體或其演算法重製。

## 核心功能

### STORM 作戰研究分析實驗室
- 戰役分析流程：系統 → 能力 → 計畫 → 執行 → 影響。
- 五種表徵：指揮管制、資產、情報管理、互動管理、環境。
- 隨機重複：30–500次批次模擬，顯示平均、標準差、百分位與90%平均值區間。
- 方案比較：以相同條件和隨機種子比較四種COA。
- 敏感度分析：逐項調整因素，觀察任務效果變化。
- 2³因子實驗：同時比較C2、ISR與後勤的高低水準與交互作用。
- 模型透明：畫面直接說明假設、資料類型、係數屬性與限制。


- LLM 想定生成：依分析重點、難度、回合、情報不確定度、民事壓力、天候與美軍支援程度生成情境；未設定 API Key 時不可使用。
- 建立想定分頁：情境範本、戰略壓力參數、合成資源清單、公開裝備名稱與品項級武器裁決、品項級武器數值預覽、補充限制及 LLM 必要設定集中於七個分頁。
- 左側建立導覽：七個建立想定分頁在桌面版改為左側垂直導覽，窄螢幕自動切換成可橫向滑動的分頁列。
- 建立想定滿寬版型：建立想定區塊自動貼合整個瀏覽器寬度，保留左右響應式留白。
- 三方品項管理：公開裝備與品項裁決依藍、紅、黃三方水平分頁篩選；新增機場、雷達站、基地、電廠與陣地等可調整物件。
- 分類預設與 LLM 補充：每個武器、設施及支援分類都有存量、可用率、保留、消耗、恢復、補充、延遲、可靠度與單位效能預設值，可直接修改或由 LLM 補充目前陣營品項。
- 三方數值預覽：品項級武器數值預覽提供藍、紅、黃分頁；內容不足寬度時以水平捲軸完整保留參數欄。
- 主功能順序：四、事後檢討與分析；五、決策時間線；六、STORM 合成化戰區作戰實驗室；七、資料庫；八、指引。
- 獨立想定頁：主功能依序為「一、建立想定、二、想定、三、回合推演」，生成完成後會直接顯示獨立的想定摘要與開始推演操作。
- 回合兵推：紅、藍、黃三方一律用自然語言提交命令；畫面不再顯示主行動、支援行動、區域或資源選單，LLM 會在背景轉成結構化命令並依武器數值裁決。
- 紅方先行與三方自然語言：紅方先行，藍方依情報回應，黃方接續支援；每方都可由使用者輸入或單獨交給 LLM 生成，也可一次補齊所有尚未下令方。
- 快速命令模板：紅、藍、黃三方各有可點選的文字模板，會加入自然語言輸入框供使用者修改，再由 LLM 生成完整戰略命令。
- 命令完稿流程：每方提供 10 種快速模板；LLM 產生內容只會成為草稿，人工修改後可再次交給 LLM 潤飾，只有按下完稿提交才正式轉換資源並寫入回合命令。
- 垂直功能列：回合推演右側功能區使用滿高版型，命令、戰局、情報、資源、次回合、白方與紀錄改為垂直選單列。
- 回合推演獨立分頁：次回合想定包與白方臨時導調事件各自納入右側垂直功能列；頁首標題列已省略以增加可用高度。
- 左側圖標說明：三方圖標說明移至回合結算動畫下方、概略情勢圖上方，並維持預設收合。
- 推演分頁版型：三方回合結算地圖固定占桌面版面三分之二，命令、戰局、情報、資源與紀錄集中於右側三分之一分頁面板。
- 回合操作列：回合指示與結算按鈕位於右側功能面板頂端；回合推演頁不顯示區塊導覽列。
- 概略情勢圖：移到三方動畫下方並預設收合，主要畫面只保留動畫。
- 命令圖標同步：主命令圖標由自然語言解析結果自動選定，保存於三方命令快照，並同步套用到回合動畫與事後重播。
- LLM 裁決文字：規則引擎先保存數值結果，再由 LLM 根據三方命令、實際品項投入、庫存期末、事件、天候、損失與重大衝突生成裁決、關鍵風險及裁決分析。
- 抽象作戰類型：新增航空攔截、防空交戰、遠程火力、海上拒止及水下警戒等教學行動；可使用公開裝備名稱作為敘事標籤，但不採用真實射程、座標、目標、庫存、命中率或交戰程序。
- 概略情勢圖：只使用北／中／南海峽、東部外海、本島整體等抽象區域。
- 情報與戰場迷霧：情報帶有來源可靠度與信心值。
- 後勤與資源：追蹤準備、持續性、指管、情報、資源及民事風險。
- 詳細資源庫存：預載三方公開裝備名稱及合成遊戲參數，可調整遊戲存量、可用率、保留比例、每次消耗、恢復與延遲補充，並支援 CSV 匯入／匯出。
- OpenStreetMap 空間配置：以本地 Leaflet 1.9.4 顯示 OSM 圖磚，同一品項可分散到多個精確配置點，並記錄各點起始與目前數量。
- 公開部署預設：範本品項使用公開基地、機場與港區的設施中心點；缺乏可靠品項級資料時明確標示為「遊戲推定位置」。所有位置都是固定版本、非即時資料，可由使用者覆寫。
- 經緯度動畫與回放：來源配置點、目標、路線、移動圖標及衝突半徑皆由 Leaflet 投影，縮放、平移與全螢幕後仍保持地理對齊；新回合保存不可變的空間快照。
- 名稱正規化：LLM 潤飾前後都會用本機庫存字典修正裝備縮寫，例如 `KC46` 會修正為 `KC-46A Pegasus`，不改變數量與單位。
- 空間化命令：實體資源依合成遊戲半徑驗證配置點至行動目標的距離；超出範圍或數量不足時禁止提交，敵對目標相距 50 公里內形成空間衝突群。
- 座標隱私：精確座標可隨 JSON／CSV 備份，但所有 LLM 請求只會收到抽象區域與匿名資源摘要。
- 品項級武器裁決：每項裝備以遊戲存量、可用率、保留比例、每次消耗、可靠度、單位效能及實際命令數量直接計算回合戰力；公開名稱不代表真實性能。
- 回合資源帳本：每回合保存期初、恢復、補充、行動消耗、事件損失與期末數量。
- 次回合想定包：固定由 LLM 依結算後資源趨勢生成情報、候選事件與決策難題；API 失敗時取消該次結算，不採本機想定備援。
- 敏感資料模式：品項名稱、原始數量及備註只留在瀏覽器；次回合想定 LLM 最多只接收匿名化類別分數與趨勢，自然語言命令中的品項則由本機比對。
- 攔截資源配置實驗：以合成機率展示資源投入與邊際效益。
- 事後檢討：滿螢幕寬度呈現主要風險、反思題與逐回合完整回看；決策時間線已獨立為最上方第五個主分頁。
- 匯入／匯出：JSON保存完整模擬狀態，CSV匯出回合紀錄。
- 本機保存：進度只存在瀏覽器 localStorage，除非主動匯出。
- 合成資源基線：可設定雙方的航空架次、攔截彈、海上平台與補給批次；這些虛構數量會影響想定摘要、起始準備與回合裁決。
- LLM 必要模式：支援 Gemini、OpenAI、Anthropic Claude 與長庚 CGU LLM API，以當前合成資源和補充限制生成想定、紅方先行事件、命令轉換及次回合想定包。未輸入 API Key 時不可建立、匯入或使用想定。
- AI 回合補齊：LLM 會依當前資源、準備度、情報、事件、天候與已提交命令生成紅方先行及缺少角色的合成命令包；API 不可用時停止流程，不使用本機命令備援。
- 模擬情境範本：提供有限封控、多軸空情、港口後勤、灰色地帶、人道疏散與危機降溫等六種合成情境。

## 單機使用

解壓縮後直接雙擊 `index.html`。

本專案不使用 ES Module、fetch 或外部 CDN，因此可在多數瀏覽器的 `file://` 模式直接執行。

若瀏覽器的本機檔案政策較嚴格，可在專案目錄執行：

```bash
python3 -m http.server 8000
```

再開啟：

```text
http://localhost:8000
```

Windows 也可雙擊 `start-local.bat`。

## GitHub Pages 部署

1. 建立新的 GitHub repository。
2. 將本專案全部檔案上傳到 repository 根目錄。
3. 進入 **Settings → Pages**。
4. Source 選擇 **Deploy from a branch**。
5. Branch 選擇 `main`，資料夾選 `/root`。
6. 儲存後等待 GitHub Pages 網址產生。

不需要 Firebase、資料庫伺服器或 API Key。

使用任何想定前，必須先在頁面輸入對應服務的 API Key。系統會將 Key 儲存在目前瀏覽器的 localStorage，不會包含在想定匯出檔；共用電腦使用完畢請按頁面上的「清除已儲存 API Key」。Gemini 的模型欄可填入帳戶可用的 `gemini-3.5-flash` 或 `gemini-3.6-flash`；實際模型名稱仍以該帳戶/API 版本提供者為準。

## 資料與安全界線

- 公開來源目錄與少量國防部公告樣本屬真實公開資料。
- 兵力、能力、庫存、妥善、損失、機率及事件結果均為合成示範。
- 預設座標只採公開設施中心點或區域遊戲推定點，不代表真實／即時單位部署；不含庫房、跑道端點、武器陣地、現役庫存、弱點、射擊表或可靠實戰效能。
- 使用者自行建立的地圖配置僅是本機合成遊戲資料；所有公里半徑都是可調整的遊戲參數，不代表公開裝備的真實性能。
- 不得用於真實目標選擇、武器配置、攔截規劃、漏洞分析或即時作戰支援。
